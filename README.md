# Maqam-classification-BiLSTM

**Problem**. Qur'anic recitation follows one of eight melodic modes (maqamat): Ajam, Bayat, Hijaz, Kurd, Nahawand, Rast, Saba, Seka. Identifying the maqam from audio alone is useful for recitation self-study tools but is a genuinely hard audio classification problem: the signal is a single unaccompanied voice, recordings vary in length (27–65s) and reciter, and the public dataset (Maqam478, Shahriar & Tariq, 2021) has only 478 recordings total. Roughly 60 per class.

**Why this dataset is tricky**. With so few recordings, the biggest risk isn't model architecture, it's data leakage. My initial instinct (and a mistake I see in a lot of published pipelines on this dataset) would be to chop each long recording into short segments first, then randomly split segments into train/test. That silently leaks information: segments from the same recording end up on both sides of the split, so the model can partly "recognize the recording" rather than the maqam.

**What I did about it**. I split at the file level first. 382 recordings for training, 96 held out for testing, stratified so each maqam is proportionally represented, before any segmentation happened. Only after that split did I merge each maqam's training recordings and cut them into fixed 30-second segments (558 training segments, 137 test segments) for feature extraction. This guarantees no audio content from a test recording ever appears in training, which is the property that actually matters for a trustworthy accuracy number.

**Feature extraction & model**. Each 30-second segment is converted to 20 MFCCs (Mel-Frequency Cepstral Coefficients) at 22.05kHz, padded/truncated to a fixed 174-frame length, giving each segment a (174, 20) time-series representation. I fed this into a bidirectional LSTM (2 layers, 128 hidden units, dropout 0.5) in PyTorch, followed by a linear classifier over the 8 classes. BiLSTM was the right architectural choice here over a plain CNN-on-spectrogram approach because maqam is defined by melodic movement over time. The sequence direction matters, and bidirectionality lets the model use both the buildup to and resolution from a melodic phrase.

**Results**. The baseline BiLSTM reached 74% test accuracy (macro F1 0.74) across the 8 classes. I then ran a 20-trial Optuna search over learning rate, hidden size, depth, and dropout, which found a configuration (256 hidden units, 2 layers, lr≈5.6e-4, dropout≈0.21) that improved accuracy to 78% (macro F1 0.79). Performance was strongest on acoustically distinctive maqams (Seka: F1 0.97, Saba: F1 0.86) and weakest on maqams that are more melodically similar to each other (Hijaz and Rast both hovered around F1 0.63–0.65), which tracks with what music theory would predict, and is a more interesting failure mode to talk about than a flat accuracy number.

**Honest limitation**. Both the early-stopping checkpoint and the Optuna search used the same held-out set that I'm reporting final accuracy on. Meaning the test set doubled as a validation set. That inflates the reported numbers somewhat versus a true one-shot holdout. The methodologically correct fix, which I'd apply in a v2, is a three-way split: a validation set for early stopping and hyperparameter search, with the test set touched exactly once at the end. I'm flagging this rather than hiding it because catching this kind of leakage is exactly the skill this project is meant to demonstrate.

**Stack**: Python, librosa, PyTorch, Optuna, scikit-learn, pandas. Full pipeline from raw audio download (Figshare API) through EDA, leakage-safe splitting, feature engineering, model training with early stopping, and hyperparameter optimization, run end-to-end in Google Colab.
